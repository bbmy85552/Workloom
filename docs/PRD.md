# Workloom 产品说明

本文描述 Workloom 当前的产品用途、功能与使用边界，作为开发和文档维护的共同依据。

## 产品定位

Workloom 是面向个人和小团队的自托管协作工作空间。它把知识整理、文档编辑、结构化信息、待办、日程、邮箱和外部 AI 工具连接起来，让资料与日常工作可以在同一个实例中持续积累。

用户可以自行部署并保存数据库和附件。管理员管理团队接入、品牌、公共内容和运行配置；普通成员按权限使用私人、公共及共享空间。

## 用户与入口

| 用户 | 主要使用方式 |
| --- | --- |
| 个人用户 | 组织资料、编辑文档、管理数据表、安排待办和日程、连接邮箱 |
| 团队成员 | 查看或编辑获授权内容，维护公共知识，参与评论与协作 |
| 内容管理者 | 整理目录与文件夹，管理分享、版本和协作者 |
| 管理员 | 配置品牌、注册策略、邀请码、OA、SMTP，管理用户、公共回收站、备份及更新 |
| 外部 AI / 脚本 | 使用用户 API Key，通过远程 MCP 或 CLI 访问获授权的文档和数据表 |

主入口包括工作台、文档、数据表、日历、邮箱、最近、OA、设置和管理后台。线上实例还提供项目记忆入口。

## 知识与文档

文档中心提供私人、公共、共享和收藏视图。文档可以按父子层级与文件夹组织，支持路径导航、网格查看、拖入整理和移动目标选择。

- 自己的私人普通文档可复制到公共知识库；文件夹不支持复制。
- 私人文档或目录树可移入公共空间。
- 管理员可把公共内容移回自己的私人空间。
- 文档可以共享、评论、收藏、归档，以及查看和恢复历史版本。

编辑器支持富文本、标题、链接、列表、图片、附件、文档内表格、查找替换和字数信息。支持粘贴图片、将 Markdown 转为富文本以及手动触发表格排版。大屏文档页和公开分享页提供标题目录与锚点导航，只读场景隐藏编辑控件。

导入支持批量 DOCX、Markdown、TXT，逐个处理并提供进度和失败反馈。导入中的图片按格式、大小和可访问性处理为附件；不保证所有外部图片都能保存。DOCX 导出处理图片和表格兼容性。

## 协作与保存

协作者的读写权限由内容授权决定。分享链接可用于访问公开内容或引导登录，登录后返回原链接。

文档保存使用自动保存、请求排队和版本检查。当远端版本发生变化时，界面提供左右对比，让用户选择使用本地版本、加载远端版本或稍后处理。这个流程不等于实时多人光标编辑，也不自动合并两个版本。

公共文档及其子树删除后软删除，管理员可以在回收站恢复选中文档和必要的已删除父链，或永久清理。恢复单项不会自动恢复其所有已删除子孙；私人文档仍直接删除。过期公共内容的清理在读取回收站时触发。

## 数据表与表单

数据表提供字段、记录、模板与公式，支持表格、看板、日历和甘特视图。字段可承载文本、数值、日期、选择项、附件、用户等信息。

用户可按内容调整列宽与对齐，使用 CSV 导入和 CSV/XLSX 导出，通过公开表单收集记录。表格权限区分所有者、编辑者与查看者。

## 工作台、待办与日历

工作台聚合待办、近期文档和日程。日历提供月、周、日视图，支持重复日程、把待办安排到日历、站内和邮件提醒。

## 邮箱与 OA

用户可绑定 IMAP/SMTP 邮箱，同步多个文件夹，在站内撰写或回复邮件、发送附件，并将邮件转为待办。

OA 地址由管理员配置，工作空间提供侧栏入口、iframe 内嵌和新窗口打开。该接入加载独立 OA 系统，不表示拥有其业务逻辑、数据同步或单点登录能力。

## 团队接入与个性化

用户通过邮箱或 Google 登录。普通注册与 Google 首次注册需要有效邀请码；管理员可关闭注册。系统提供密码与邮箱管理、会话记录和远程注销。

品牌与公司名应用于界面、认证页面和系统邮件。个人设置包括外观、主题、默认首页、编辑器字号、邮箱同步和字体记录。

## AI 与命令行

用户在“设置 → AI 与 CLI”生成 API Key。远程 MCP 使用 Streamable HTTP，通过实例的 `/mcp` 端点提供文档、数据表、字段和记录工具；CLI 使用相同用户权限。

CLI 入口为 `npm run workloom -- ...` 或 `node scripts/workloom-cli.mjs ...`，连接配置为 `WORKLOOM_BASE_URL` 与 `WORKLOOM_API_KEY`。具体工具和参数见 [MCP_USAGE.md](../MCP_USAGE.md)。

线上项目记忆按项目沉淀事实、决策和偏好，提供个人、公共和共享项目入口与专用记忆 MCP。

## 部署与运行

前端使用 React、TypeScript、Vite 和 TipTap；服务端使用 Express、Prisma 与 SQLite。Docker Compose 运行 `workloom` 服务，数据库和上传文件分别持久化。

首次初始化创建管理员并验证 SMTP。管理后台提供用户、用户组、系统设置、审计、备份恢复、迁移和更新管理。部署配置见 [配置说明.md](../配置说明.md)，维护流程见 [MAINTENANCE.md](MAINTENANCE.md)。

**部署备注：** 线上项目记忆及专用记忆 MCP 尚未同步至当前公开源码。本文对它们的描述对应线上实例，克隆部署范围以仓库中的路由和业务实现为准。
